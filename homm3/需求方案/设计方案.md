# 英雄无敌3 复刻版 —— 设计方案

> 配套《需求文档.md》；描述模块架构、核心算法与关键数据结构。

## 1. 总体架构

```
homm3/
├── main.py        # 场景状态机 + Game 中央状态 + 敌方 AI 回合
├── world.py       # 地图生成 + A* 寻路 + World 状态容器
├── combat.py      # 六边形战棋引擎（可无头模拟）+ 魔法 + auto_resolve
├── entities.py    # UnitType / Hero / Town / 宝物 / 建筑等纯数据模型
├── constants.py   # 网格尺寸、资源、地形、对象类型等常量
├── savegame.py    # JSON 序列化/反序列化（往返重建 Game）
├── sounds.py      # numpy 波形合成音效（懒初始化、可静音）
└── test_smoke.py  # 无头冒烟测试（SDL dummy 驱动）
```

**分层原则**：`entities` 为纯数据；`combat`/`world` 为无 UI 引擎（可在无头环境完整运行）；`main.py` 持有全部渲染与事件；`savegame` 只做状态搬运。引擎层不 import pygame（除 combat 引音效钩子，sounds 在无 mixer 时自动 no-op）。

## 2. 场景状态机（main.py）

```
Game（中央状态：world / heroes / active_idx / msg）
 ├── AdventureScene   冒险地图：移动/交互/敌方进攻触发
 ├── TownScene        城镇：建造/招募/雇英雄/转兵/市场
 ├── CombatScene      战斗：六边形战棋 UI + 法术选择
 └── GameOverScene    失败画面
```

- 统一接口：`handle_event(ev)` / `update(dt)` / `draw(screen, fonts)`
- 读档：`handle_event` 返回新 `Game`，主循环替换实例（F9）
- `CombatScene` 构造参数泛化：`(game, enemy_army, enemy_hero, on_win)` 回调分别处理野怪清除/敌将阵亡/攻城易主

## 3. 世界模型（world.py）

- `terrain: MAP_W×MAP_H`，PASSABLE={grass, dirt}
- `objects: {(x,y) -> dict}`，按 `type` 字段区分资源/矿/宝箱/宝物/野怪/城镇/祭坛
- 生成策略：随机障碍块（水 45% 倾向）→ 泥土点缀 → `place()` 按空位随机投放（城镇 3×3 清障）
- 野怪强度 = f(离玩家城距离)：远端 35% 概率绿龙，其余按距离放大数量
- **A\***：曼哈顿启发式，四方向；对象格默认可走（走上去即触发交互）

## 4. 战斗引擎（combat.py）

### 4.1 六边形拓扑

- odd-r 偏移坐标（奇数行右移半格），尖顶六边形
- `hex_neighbors(c,r)`：偶行/奇行两套 6 邻居表
- `hex_dist`：转 cube 坐标 `(x, y=-x-z, z)` 取三轴差最大值
- `move_reachable`：BFS 限 `eff_speed` 步，单位互不穿越

### 4.2 单位与伤害

- `BUnit`：血池模型 `total = count × hp`，受伤按池折算死亡数；`start_count` 限定治疗上限
- 伤害：`count × rand(dmin,dmax)` × 攻防修正（+5%每点优势至3倍 / -2.5%每点劣势至0.3倍）
- 近战被反击一次/轮；运气（5%×luck）双倍；吸血按造成伤害 `heal()` 回数
- 士气：`next_unit()` 里对刚行动单位掷骰（5%×morale），命中则插队首再动

### 4.3 行动队列

```
new_round(): 重置反击/等待 → alive 按 (-eff_speed, side, uid) 排队
next_unit(): 弹出下一个存活单位；队列空则判胜负或开新一轮
ai_act():    最近敌人 → 远程射击 / 近战找目标邻格可达位 → 否则逼近
auto_resolve(): AI vs AI 无头打完，返回 (胜负, 双方幸存) —— 敌将打野、E2E 测试复用
```

### 4.4 魔法

`cast(spell_key, target)` 统一校验（每轮一次/耗蓝/目标阵营），火球遍历目标六邻居溅射同侧单位。

## 5. 英雄与属性合成（entities.py）

- `Hero` 持 `artifacts: [key]`，属性走合成函数：
  `atk_total = atk_bonus + Σ宝物atk`，`morale = Σ宝物morale − 混编惩罚`
- 混编判定：`army` 中 `utype.faction` 去重后 >1 则 -1
- `equip()` 时 mana 类宝物同时加当前法力与上限

## 6. 敌方 AI（main.Game.enemy_turn）

```
每日：周一增援（骷髅/僵尸随天数缩放，day≥14 +吸血鬼，day≥28 +巫妖）
     A* 到最近玩家英雄 → 逐步走 ≤10 格：
       · 下一步是玩家英雄 → 锁定为 active 并标记 enemy_attacks（场景 update 时开战斗）
       · 下一步是野怪 → auto_resolve 打，胜则清怪/败则敌将阵亡
```

## 7. 存档设计（savegame.py）

- 全量 JSON：地形二维数组 / objects 按 `"x,y"` 键 / 军队按 unit key / 城镇按名回链 / 英雄逐字段
- `World.blank()` 跳过生成构造空世界；`load()` 重建 Game 并接管场景
- 往返一致性由测试断言（存前 vs 读后逐项相等）

## 8. 音效设计（sounds.py）

- `SR=22050` 合成；`init()` 先 `mixer.quit()` 重置到目标采样率避免变调，立体声 mixer 自动 `column_stack` 双声道
- 原语：`_tone(freq|sweep, dur, vol, wave, decay)` + `_noise`，指数衰减包络
- 播放入口 `play(name)` 三重守卫（enabled / _ready / 存在性），无声卡环境静默

## 9. 渲染方案（程序绘制）

| 元素 | 画法 |
|---|---|
| 地形 | 平涂色块网格 |
| 资源/矿/宝箱/宝物 | 圆/矩形/三角形，按槽位配色 |
| 野怪 | 兵种色圆 + 红圈 + 数量角标 |
| 英雄 | 白圆 + 三角帽徽，激活黄圈，敌将红色 |
| 战场 | 六边形多边形（`hex_points` 生成），移动范围缩放 0.82 高亮 |
| 单位 | 圆角矩形色块 + `数量|速度` 角标 + 名字 |

- 鼠标拾取：遍历六边形中心取最近且半径 <34px（117 格往返测试保证精确）
- 中文字体：`SysFont` 按候选链回退（PingFang/STHeiti/微软雅黑等）

## 10. 测试策略（test_smoke.py，无头可跑）

| 类别 | 断言 |
|---|---|
| 世界 | 多种子生成完整性、寻路 |

## 11. 关键权衡记录

| 决策 | 理由 |
|---|---|
| 方格先行、R6 再改六边形 | 先闭环玩法，降低首版风险；odd-r 抽象隔离使替换只动邻接/距离/渲染 |
| 血池伤害模型（无个体 HP 跟踪） | 实现简单、可序列化；代价是治疗只能按数量近似 |
| 军队用 `dict{UnitType:int}` 而非 7 槽列表 | 同型兵自动合并，省去分队 UI；分兵需求用"英雄间转移"替代 |
| 敌将打野用 auto_resolve 而非进场景 | 保持冒险地图节奏，引擎复用保证一致性 |
| 宝物自动装备（无卸下/交换） | 简化 UI；加成全为正向无需取舍 |
| 音效合成而非素材文件 | 零版权 + 仓库自包含； mixer 采样率/声道自适应兜底 |
