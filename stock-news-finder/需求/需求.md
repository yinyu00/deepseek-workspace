# 股票新闻分析系统 · 需求文档

> 版本：v0.8（2026-09-14）
> 状态：原型已跑通部分功能，本文档梳理完整需求，作为后续迭代基线
> 定位声明：**研究漏斗**——每天从全市场信息中筛出少量候选股票供人工研究，**不是**自动交易系统
> 运行模式：**手动触发**（v0.3 起，定时任务已移除；理由见 D10）

## 1. 系统目标

通过网络新闻与一手披露数据发现可能上涨的股票：

- 输入：每日财经信息流（快讯、公告、龙虎榜、互动易、机构调研、研报摘要）
- 处理：信息 → 关联股票 → 事件分类 → 打分排序 → 提纯分级推荐
- 输出：每日信号报告（TOP30 候选）+ **推荐日报（三档分级）** + 推荐复盘（次日验证）
- 原则：可解释性优先——每条推荐必须能回答"为什么推荐"

## 2. 分层架构

```
采集层 → 解析层 → 关联层 → 信号层 → 推荐层 → 验证层 → 展示层
```

| 层 | 职责 | 现状 |
|---|---|---|
| 采集层 | 多源信息抓取、去重 | ✅ **插件化（9 源）**：4 个一手源（巨潮公告/龙虎榜/互动易/机构调研）+ 5 个新闻源 |
| 解析层 | 事件分类、情感/影响判断 | ✅ GLM API 分类（9类事件）+ 正则规则降级 |
| 关联层 | 信息 → 股票映射 | ✅ 公司直接命中 + 产品板块传导 + 官方标注（词典外可发现） |
| 信号层 | 综合打分排序 | ✅ 影响分×置信度×命中强度×时效衰减×**权威加成** |
| 推荐层 | 信号提纯 + 三档分级 | ✅ **v0.8 新建**（recommend.py）：产品传导噪声不入推荐、强事件分级、交叉验证、连续性加成 |
| 验证层 | 推荐复盘、命中率统计 | ✅ **v0.8 首建**（review.py）：次日行情回看 + 分档累计统计（F7.2/F7.3 部分实现） |
| 展示层 | 报告查看、告警推送 | ✅ 信号/推荐/复盘三类日报；企业微信群机器人（主）+ Server酱（备） |

### 3.9 实体信息累积层（2026-09-15 立项，模型定义已完成）

> 背景：实测新闻对「法人个人司法风险」覆盖率 ≈ 0（18 天 × 934 条仅 2 条泛命中），
> 但新闻对「公司级事件」和「人物动态（人事变动/被调查/减持）」有持续增量。
> 本层把每日新闻中的实体信息**结构化累积**成自有数据库，服务三个用途：
> ① 法人风险精查的消歧上下文（这个人关联哪些公司）② 人物舆情速查 ③ 关系网络分析（远期）。
> 每条记录必须带**原文 URL + 内容快照**（防撤回），模型详见方案文档 2.11。

## 9. 术语约定

- **命中**：新闻文本中出现词典词项（公司名/别名/产品词）
- **传导**：产品词 → 板块成分股的间接关联
- **信号分**：单条新闻对单只股票的打分；**综合分**：该股当日全部信号分之和
- **一手源**：官方/交易所直接披露（公告/龙虎榜/互动易/机构调研），享 ×1.5 权威加成；新闻为二手转述
- **强事件**：可作推荐依据的事件类型（订单/政策/业绩/并购/回购/产品进展/资金异动/机构调研）；弱事件只作热度
- **推荐分**：推荐层重算的分（强事件为主+交叉/连续性加成），与信号分并列展示
- **日报**：daily/ 下三类——yyyymmdd.md（信号）、recommend_yyyymmdd.md（推荐）、review_yyyymmdd.md（复盘）
- **插件**：fetchers/<type>.py 采集器模块（fetch + selftest 接口，见 fetchers/SPEC.md）
